# GET, POST, PUT, PATCH, DELETE Semantics in FastAPI

This is one of the most important REST API topics.

Many beginners know:

```python
@app.get()

@app.post()

@app.put()

@app.patch()

@app.delete()
```

But they don't know:

> Why do we have different HTTP methods if all of them can send and receive data?

The answer is:

# Semantics

Semantics means:

> The intended meaning of the operation.

Think of traffic signals.

```text
🟢 Green  = Go

🟡 Yellow = Be Careful

🔴 Red    = Stop
```

Technically, you could ignore them.

But everyone follows the meaning.

Similarly:

```text
GET    = Read Data

POST   = Create Data

PUT    = Replace Data

PATCH  = Update Partially

DELETE = Remove Data
```

# 3. PUT

## Meaning

```text

```

This is where many students get confused.

PUT means:

> Replace the existing object with a new version.

---

```json

  "id":101,

  "age":21,

}
```

---

PUT Request

```json
  "name":"Rahul",

```

---

Result

```json
  "id":101,
  "name":"Rahul",
  "age":22,
  "department":"ECE"
}
```

Entire object replaced.

# CREATE (POST)

Create a new student.

```python
@app.post("/students")
def create_student(student: dict):

    student_id = max(students.keys()) + 1

    student["id"] = student_id

    students[student_id] = student

    return {
        "message": "Student Created",
        "student": student
    }
```

```json
  "age": 23
}
```

```json
    "age": 23

}
```

# READ ONE (GET)

Get a specific student.

```python
@app.get("/students/{student_id}")
def get_student(student_id: int):

    if student_id not in students:

        raise HTTPException(
            status_code=404,
            detail="Student Not Found"

    return students[student_id]
```

# UPDATE (PUT)

Replace entire student record.

```python
@app.put("/students/{student_id}")
def update_student(
    student_id: int,

    if student_id not in students:

        raise HTTPException(

            detail="Student Not Found"

    student["id"] = student_id

    students[student_id] = student

    return {
        "message": "Student Updated",
        "student": student
    }
```

## Request

```http
PUT /students/1
```

# PARTIAL UPDATE (PATCH)

Update only changed fields.

```python
@app.patch("/students/{student_id}")
def patch_student(
    student_id: int,
    data: dict
):

    if student_id not in students:

        raise HTTPException(
            status_code=404,
            detail="Student Not Found"
        )

    students[student_id].update(data)

    return {
        "message": "Student Patched",
        "student": students[student_id]
    }
```

---

## Request

```http
PATCH /students/1
```

Body:

```json
{
  "age": 30
}
```

---

## Before

```json
{
  "id":1,
  "name":"Ravi",
  "age":21
}
```

---

## After

```json
{
  "id":1,
  "name":"Ravi",
  "age":30
}
```

Only age changed.

---

# DELETE

Remove a student.

```python
@app.delete("/students/{student_id}")
def delete_student(student_id: int):

    if student_id not in students:

        raise HTTPException(
            status_code=404,
            detail="Student Not Found"
        )

    deleted_student = students.pop(student_id)

    return {
        "message": "Student Deleted",
        "student": deleted_student
    }
```

---

## Request

```http
DELETE /students/1
```

---

## Response

```json
{
  "message":"Student Deleted",
  "student":{
      "id":1,
      "name":"Ravi",
      "age":21
  }
}
```

# How Industry Actually Does It

This example is for understanding CRUD.

In production:

```text
Client
  ↓
FastAPI Route
  ↓
Pydantic Validation
  ↓
Service Layer
  ↓
Database Layer
  ↓
MongoDB/PostgreSQL
```

Instead of:

```python
student: dict
```

industry uses:

```python
class Student(BaseModel):
    name: str
    age: int
```

which gives:

```text
Validation
Swagger Schema
Type Safety
Better Error Handling
```
