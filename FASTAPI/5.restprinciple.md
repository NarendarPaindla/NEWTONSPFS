# REST Principles (The Foundation of Modern APIs)

Before learning FastAPI routes like:

```python
@app.get()
@app.post()
@app.put()
@app.delete()
```

You must understand **REST**.

Because when companies build APIs using FastAPI, Spring Boot, Node.js, Django, or .NET, they usually follow REST principles.

---

# First Question

## What is REST?

REST stands for:

```text
REpresentational
State
Transfer
```

It was introduced by:

Roy Fielding

in his PhD dissertation in 2000.

---

# Simple Definition

REST is an architectural style that defines how clients and servers should communicate over HTTP.

Simple version:

> REST provides rules for designing APIs in a standard and predictable way.

Without REST:

Developer A:

```text
/getStudents
```

Developer B:

```text
/fetchAllStudentData
```

Developer C:

```text
/student_list
```

Everything becomes inconsistent.

REST brings standardization.

---

# Real-Life Example

Imagine driving.

Every country follows traffic rules:

```text
Red   -> Stop
Green -> Go
Yellow -> Wait
```

Because everyone follows the same rules.

Similarly:

REST defines API rules.

---

# Why REST Was Needed?

Suppose Amazon, Netflix, Instagram, and Swiggy all created APIs differently.

Frontend developers would struggle.

REST provides a common language.

# REST Principle 1: Client-Server Separation

One of the most important principles.

---

## Meaning

Frontend and Backend should be independent.

```text
Frontend
   |
API
   |
Backend
```

Frontend should not directly access database.

---

# Wrong Architecture

```text
React
   |
Database
```

Dangerous ❌

---

# Correct Architecture

```text
React
   |
FastAPI
   |
Database
```

REST promotes separation.

---

# Industry Example

Instagram

Frontend:

* Mobile App
* Website

Backend:

* APIs

Database:

* User data

Each layer is independent.

---

# Benefit

Backend can change without changing frontend.

Example:

```text
MySQL
```

to

```text
PostgreSQL
```

Frontend won't care.

---

# REST Principle 2: Statelessness

Interview Favorite.

---

## Meaning

Every request must contain all information required to process it.

Server should not remember previous requests.

---

Example:

Request 1

```http
GET /profile
```

Completed.

---

Request 2

```http
GET /orders
```

Server treats it as new request.

---

# Real-Life Example

ATM Machine

You insert card.

ATM verifies.

Transaction completed.

Next user starts fresh.

ATM doesn't remember previous customer.

---

# Why Stateless?

Benefits:

✅ Scalability

✅ Simplicity

✅ Reliability

✅ Easy Load Balancing

---

# Example

Bad:

```text
Server remembers all users
```

Hard to scale.

---

Good:

```text
Each request contains token
```

Easy to scale.

---

✅ Better performance

# CRUD and REST


# FastAPI Example

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/students")
def get_students():
    return []

@app.post("/students")
def create_student():
    return {"message":"created"}

@app.put("/students/{id}")
def update_student(id:int):
    return {"message":"updated"}

@app.delete("/students/{id}")
def delete_student(id:int):
    return {"message":"deleted"}
```

Notice something?

```text
Resource = students
Action = HTTP Method
```

This is REST thinking.

# Golden Rule

When designing APIs, think:

```text
Resource First
Action Second
```

Not:

```text
/createStudent
/deleteStudent
```

Think:

```text
/students
```

Then use HTTP methods:

```text
GET
POST
PUT
DELETE
```

That mindset is what separates a beginner from a professional backend developer.
