# Response Formatting in FastAPI

Till now we have been returning responses like:

```python
@app.get("/")
def home():
    return {
        "message": "Hello FastAPI"
    }
```

Response:

```json
{
  "message": "Hello FastAPI"
}
```

Looks simple.

But in real companies:

```text
Amazon
Flipkart
Netflix
Instagram
Banking Systems
```

responses follow a consistent format.

Why?

Because frontend developers consume these APIs.

A well-formatted response makes frontend development much easier.

---

# What is Response Formatting?

Response Formatting means:

> Structuring API responses in a predictable and consistent way.

Instead of:

```json
{
  "name":"Ravi"
}
```

we return:

```json
{
  "success": true,
  "message": "Student Retrieved Successfully",
  "data": {
      "name":"Ravi"
  }
}
```

Much cleaner.

---

# Why Response Formatting Matters?

Imagine API 1 returns:

```json
{
  "name":"Ravi"
}
```

API 2 returns:

```json
{
  "student":"Ravi"
}
```

API 3 returns:

```json
{
  "result":"Ravi"
}
```

Frontend developer gets confused.

---

Good APIs return:

```json
{
  "success": true,
  "message": "...",
  "data": {}
}
```

everywhere.

Consistency matters.

# Error Response

Using HTTPException:

```python
from fastapi import HTTPException

@app.get("/students/{student_id}")
def get_student(student_id: int):

    raise HTTPException(
        status_code=404,
        detail="Student Not Found"
    )
```

---

Response:

```json
{
  "detail":"Student Not Found"
}
```

---

# Real Industry Error Format

Many companies return:

```json
{
  "success": false,
  "message": "Student Not Found",
  "error_code": 404
}
```

This is usually implemented using custom exception handlers (later topic).

---

# Custom Status Code

Example:

```python
from fastapi import status

@app.post("/students")
def create_student():

    return {
        "message":"Created"
    }
```

Default:

```http
200 OK
```

But creation should be:

```http
201 Created
```

---

Correct:

```python
from fastapi import status

@app.post(
    "/students",
    status_code=status.HTTP_201_CREATED
)
def create_student():

    return {
        "message":"Student Created"
    }
```

---

Response:

```http
201 Created
```

# Industry Best Practice

For most CRUD APIs, use this structure:

```json
{
  "success": true,
  "message": "Operation Successful",
  "data": {}
}
```

And for errors:

```json
{
  "success": false,
  "message": "Something Went Wrong"
}
```

This makes your APIs look professional and easier to integrate with React, Angular, Flutter, or any frontend application.
