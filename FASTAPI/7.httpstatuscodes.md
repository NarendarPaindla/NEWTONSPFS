# HTTP Status Codes — The Language of Success and Failure

When a client sends a request to a server, the server doesn't just send data back.

It also sends a **Status Code**.

Think of Status Codes as the server's way of saying:

```text
✅ Success
❌ Error
⚠ Redirect
ℹ Information
```

Without status codes, the client would never know whether the request succeeded or failed.

---

# Real-Life Example

Imagine you applied for a job.

Possible responses:

```text
Application Accepted
Interview Scheduled
Rejected
Position Closed
```

Each response tells you what happened.

Similarly, servers use status codes.

---

# Simple Definition

HTTP Status Codes are 3-digit numbers sent by the server to indicate the result of a client's request.

Example:

```http
HTTP/1.1 200 OK
```

Here:

```text
200 = Status Code
OK  = Meaning
```

---

# Why Are Status Codes Important?

Suppose your React application sends:

```http
GET /students
```

Without status codes:

```text
Did request succeed?
Did server crash?
Was user unauthorized?
```

Nobody knows.

Status codes solve this problem.

---

# Status Code Categories

Every status code belongs to a family.

```text
1xx → Information
2xx → Success
3xx → Redirection
4xx → Client Errors
5xx → Server Errors
```

Memorize this.

Almost every interview asks it.

---

# Visual Memory Trick

```text
100 → Info

200 → Success 😊

300 → Redirect ↪

400 → Client Mistake 😓

500 → Server Problem 🔥
```

# 204 No Content

Meaning:

```text
Operation successful
But no data returned
```

Often used after delete operations.

Example:

```http
DELETE /students/1
```

Response:

```http
204 No Content
```

No response body needed.

# Difference Between Authentication and Authorization

Authentication:

```text
Who are you?
```

Authorization:

```text
What are you allowed to do?
```

Many students confuse these.

# 422 Unprocessable Entity

FastAPI Interview Favorite.

FastAPI returns this very often.

---

Example:

```python
@app.get("/students/{id}")
def get_student(id:int):
    pass
```

Request:

```http
GET /students/abc
```

Expected:

```text
Integer
```

Received:

```text
String
```

Response:

```http
422 Unprocessable Entity
```

---

# Why FastAPI Uses 422

Because request format is correct.

But validation failed.

---

# Interview Questions

### What are HTTP Status Codes?

Three-digit numbers indicating the outcome of an HTTP request.

---

### Difference between 401 and 403?

```text
401 → Authentication required

403 → Authenticated but not authorized
```

---

### Which status code is used when creating a resource?

```text
201 Created
```

---

### Which status code indicates validation failure in FastAPI?

```text
422 Unprocessable Entity
```

---

### Which status code indicates server failure?

```text

```

# Golden Rule for FastAPI Developers

Whenever an API fails, first check:

```text
Status Code
      ↓
Understand Category
      ↓
Identify Problem
      ↓
Fix Issue
```

A professional backend developer can often diagnose a problem just by seeing:

```http
404
401
422
500
```

because status codes tell the story of what happened inside the Request–Response Lifecycle.
