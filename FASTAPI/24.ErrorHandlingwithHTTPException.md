# Error Handling with HTTPException in FastAPI

Until now our APIs always returned success.

Example:

```python
@app.get("/students/{student_id}")
def get_student(student_id: int):
    return {
        "id": student_id,
        "name": "Ravi"
    }
```

But real applications don't always succeed.

Examples:

```text
Student Not Found
User Not Found
Product Out of Stock
Invalid Credentials
Unauthorized Access
```

What should happen?

Should the server crash?

❌ No

Should it return random messages?

❌ No

Instead, APIs return proper HTTP error responses.

FastAPI provides:

# HTTPException

---

# What is HTTPException?

HTTPException is FastAPI's built-in way of returning HTTP errors.

Think:

```text
Normal Return
      ↓
Success Response

HTTPException
      ↓
Error Response
```

---

# Real-Life Example

Suppose a student asks:

```http
GET /students/999
```

But student 999 doesn't exist.

Server should say:

```text
Student Not Found
```

with a proper HTTP status code.

# First HTTPException Example

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()

@app.get("/students/{student_id}")
def get_student(student_id: int):

    if student_id != 1:
        raise HTTPException(
            status_code=404,
            detail="Student Not Found"
        )

    return {
        "id": 1,
        "name": "Ravi"
    }
```

# Understanding raise

Notice:

```python
raise HTTPException(...)
```

Not:

```python
return HTTPException(...)
```

---

Why?

Because:

```text
raise
```

immediately stops execution.

---

Example

```python
@app.get("/")
def home():

    raise HTTPException(
        status_code=404,
        detail="Error"
    )

    print("Hello")
```

This line never executes:

```python
print("Hello")
```

---

# Structure of HTTPException

```python
raise HTTPException(
    status_code=404,
    detail="Student Not Found"
)
```

---

# status_code

Represents HTTP status.

Examples:

```text
200 OK
201 Created
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
500 Internal Server Error
```

---

# detail

Error message sent to client.

Example:

```python
detail="Student Not Found"
```

Response:

```json
{
  "detail":"Student Not Found"
}
```

# Common HTTP Status Codes

---

## 400 Bad Request

Client sent invalid request.

```python
raise HTTPException(
    status_code=400,
    detail="Invalid Input"
)
```

---

Example

```json
{
  "detail":"Invalid Input"
}
```

---

## 401 Unauthorized

Authentication required.

```python
raise HTTPException(
    status_code=401,
    detail="Please Login"
)
```

---

Example

```json
{
  "detail":"Please Login"
}
```

---

## 403 Forbidden

Logged in but not allowed.

```python
raise HTTPException(
    status_code=403,
    detail="Access Denied"
)
```

---

Example

Admin page:

```text
Student tries to access Admin API
```

Response:

```http
403 Forbidden
```

---

## 404 Not Found

Most common.

```python
raise HTTPException(
    status_code=404,
    detail="Student Not Found"
)
```

---

## 500 Internal Server Error

Unexpected server problem.

Usually not raised manually.

Occurs due to bugs.

# Common Beginner Mistakes

Wrong:

```python
return HTTPException(
    status_code=404,
    detail="Not Found"
)
```

---

Correct:

```python
raise HTTPException(
    status_code=404,
    detail="Not Found"
)
```

---

Using 200 for errors.

```python
    "error":"Student Not Found"
```

Status still:


Misleading.

---

Correct:

```python

    status_code=404,
```

# Interview Questions

### What is HTTPException?

A FastAPI exception used to return HTTP error responses.

---

### How do we use it?

```python
raise HTTPException(
    status_code=404,
    detail="Not Found"
)
```

---

### Why use `raise` instead of `return`?

Because exceptions stop execution immediately and generate proper error responses.

---

### What is the purpose of `detail`?

It contains the error message returned to the client.

---

### What is the most commonly used status code?

```http
404 Not Found
```

for missing resources.

---

# Golden Rule

Whenever something goes wrong:

```text
Student Missing
Product Missing
Unauthorized User
Invalid Input
Access Denied
```

Don't return:

```json
{
  "error":"Something Wrong"
}
```

with status 200.

Instead:

```python
raise HTTPException(
    status_code=<appropriate_code>,
    detail="<meaningful_message>"
)
```

This is the professional way to build REST APIs and is used in almost every production FastAPI application.
