# Server-Rendered Apps vs SPA (Single Page Applications)

This is a very important architecture topic because students often ask:

```text
If React exists,
why do we need Jinja2?

If Jinja2 exists,
why do we need React?
```

The answer is:

> Both solve different problems.

---

# First Understand The Evolution

## Era 1: Traditional Websites

```text
Browser
   ↓
Request
   ↓
Server
   ↓
HTML
   ↓
Browser
```

Technologies:

```text
PHP
Django
Flask
FastAPI + Jinja2
ASP.NET MVC
```

Every click reloads the page.

---

## Era 2: SPA

```text
Browser
   ↓
React
   ↓
API Calls
   ↓
FastAPI
   ↓
JSON
```

Page loads once.

After that:

```text
No Full Page Reload
```

Only data changes.

---

# What is Server-Side Rendering (SSR)?

Example:

```text
GET /
```

FastAPI:

```python
return templates.TemplateResponse(
    "home.html"
)
```

Server generates:

```html
<html>
<h1>Welcome Ravi</h1>
</html>
```

and sends it.

---

# SSR Architecture

```text
Browser
   ↓
GET /students
   ↓
FastAPI
   ↓
Jinja2
   ↓
HTML
   ↓
Browser
```

---

# What is SPA?

SPA means:

```text
Single Page Application
```

Example:

```text
React
Angular
Vue
```

Server does NOT generate HTML.

Server only sends:

```json
{
  "name":"Ravi"
}
```

Frontend generates UI.

---

# SPA Architecture

```text
Browser
   ↓
React
   ↓
GET /api/students
   ↓
FastAPI
   ↓
JSON
   ↓
React Updates Screen
```

# Student Management Example

## SSR

```text
/students
```

FastAPI:

```python
@app.get("/students")
def students():

    return templates.TemplateResponse(
        "students.html"
    )
```

Returns:

```html
<table>
...
</table>
```

---

## SPA

FastAPI:

```python
@app.get("/api/students")
def students():

    return students_data
```

Returns:

```json
[
  {
    "id":1,
    "name":"Ravi"
  }
]
```

---

React:

```jsx
students.map(student => (
    <li>{student.name}</li>
))
```

React builds UI.

---

# Advantages of Server Rendered Apps

## Simpler

Only:

```text
FastAPI
Jinja2
HTML
CSS
```

No React needed.

---

## Faster Initial Load

HTML already generated.

Browser displays immediately.

---

## Better SEO

Google sees:

```html
<h1>Python Course</h1>
```

directly.

Excellent for:

```text
Blogs
News Websites
Documentation
Marketing Websites
```

---

## Easier Deployment

Single application:

```text
FastAPI
+
Templates
```

Deploy once.

---

# Disadvantages of Server Rendered Apps

Every page change:

```text
Reload
Reload
Reload
```

Less interactive.

---

Harder to build:

```text
Instagram
Facebook
Gmail
Netflix
```

style experiences.

---

# Advantages of SPA

## Amazing User Experience

No page refresh.

Feels like desktop software.

---

## Highly Interactive

Perfect for:

```text
Dashboards
Admin Panels
Chat Applications
ERP Systems
CRM Systems
```

---

## Frontend & Backend Separation

Backend:

```text
FastAPI
```

Frontend:

```text
React
```

Can scale independently.

---

# Disadvantages of SPA

More complexity.

Need:

```text
React
Routing
State Management
API Integration
Authentication
Build Tools
```

---

Initial load can be slower.

---

SEO requires additional work.

# When I Use Jinja2 in FastAPI

I choose Jinja2 for:

```text
Admin Dashboards
Internal Tools
Reports
Invoices
PDF Generation
Email Templates
Small Applications
```

---

# When I Use React + FastAPI

I choose React when application needs:

```text
Real-time Updates
Rich UI
Complex Forms
Dashboards
Charts
Authentication
Mobile App APIs
```

# Comparison Table

| Feature           | Server Rendered | SPA              |
| ----------------- | --------------- | ---------------- |
| HTML Generated By | FastAPI         | React            |
| Data Format       | HTML            | JSON             |
| Page Reloads      | Yes             | No               |
| SEO               | Excellent       | Extra Work       |
| Complexity        | Low             | High             |
| Initial Load      | Faster          | Slower           |
| Interactivity     | Limited         | Excellent        |
| Best For          | Blogs, Websites | Dashboards, Apps |

# For Your Students

If you're teaching FastAPI from scratch, I recommend this progression:

```text
Phase 1
HTML
CSS
JavaScript

↓

Phase 2
FastAPI APIs

↓

Phase 3
Jinja2 Templates

↓

Phase 4
React + FastAPI

↓

Phase 5
Production Full Stack
```

This helps students understand how web applications evolved and why modern companies commonly use:

```text
React
+
FastAPI
+
PostgreSQL/MongoDB
```

for large-scale applications, while still using **Jinja2** for internal tools, admin panels, reports, and lightweight applications. 🚀
