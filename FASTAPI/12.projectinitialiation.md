# Project Initialization in FastAPI

Before writing APIs, professional developers first create a proper project structure.

Many beginners do this:

```text
project/
   |
   ├── main.py
```

For learning, it's okay.

But in industry:

```text
100 APIs
50 Models
20 Developers
3 Databases
```

One file becomes impossible to manage.

That's why project initialization is important.

---

# What is Project Initialization?

Project initialization means:

> Setting up the project structure, environment, dependencies, and configuration before development begins.

Think of building a hospital.

You don't start by treating patients.

First:

```text
Building
Rooms
Reception
Departments
Equipment
```

must be organized.

Similarly for FastAPI.

---

# Real Industry Workflow

When a company starts a FastAPI project:

```text
Requirement Gathering
        ↓
Project Initialization
        ↓
Database Setup
        ↓
API Development
        ↓
Testing
        ↓
Deployment
```

# Step 2: Create Virtual Environment

## Why?

Suppose your laptop has:

```text
FastAPI 0.95
```

Project requires:

```text
FastAPI 0.120
```

Conflicts happen.

Solution:

```text
Virtual Environment
```

---

## Create Environment

Windows/Linux/Mac:

```bash
python -m venv venv
```

Creates:

```text
student-management-system/
│
├── venv/
```

# Industry-Level Structure

Most FastAPI projects eventually become:

```text
student-management-system/
│
├── app/
│   ├── routes/
│   ├── models/
│   ├── schemas/
│   ├── services/
│   ├── database/
│   └── core/
│
├── tests/
│
├── main.py
│
├── requirements.txt
│
└── .env
```

Let's understand each folder.

---

# app/

Main application package.

Contains actual business code.

---

# routes/

Contains API endpoints.

Example:

```text
routes/
│
├── student.py
├── faculty.py
├── admin.py
```

---

Example:

```python
from fastapi import APIRouter

router = APIRouter()

@router.get("/")
def get_students():
    return []
```

---

# Why?

Instead of:

```text
1000 lines in main.py
```

we separate features.

---

# models/

Database models.

Example:

```text
Student
Faculty
Department
Course
```

---

MongoDB Example:

```python
class Student:
    pass
```

SQLAlchemy Example:

```python
class Student(Base):
    pass
```

---

# schemas/

One of the most important folders.

Contains:

```text
Request Models
Response Models
Validation Models
```

Using Pydantic.

---

Example:

```python
from pydantic import BaseModel

class StudentCreate(BaseModel):
    name:str
    age:int
```

---

# Why Separate Models and Schemas?

Many beginners confuse them.

---

## Model

Database structure.

---

## Schema

API data validation structure.

---

Industry always separates them.

---

# services/

Contains business logic.

---

Example:

Bad:

```python
@app.post("/students")
def create_student():
    # 100 lines of logic
```

---

Good:

```python
@app.post("/students")
def create_student():
    return student_service()
```

---

Actual logic:

```python
def student_service():
    pass
```

inside services folder.

---

# Benefits

Cleaner code.

Easy testing.

Reusable logic.

---

# database/

Database connection files.

---

Example:

```text
database/
│
├── connection.py
├── session.py
```

---

Contains:

```text
MongoDB Connection
PostgreSQL Connection
MySQL Connection
```

---

# core/

Project-wide settings.

Examples:

```text
Configuration
Environment Variables
Security
JWT Settings
```

---

Example:

```python
SECRET_KEY
DATABASE_URL
```

---

# tests/

Contains testing code.

Example:

```text
tests/
│
├── test_students.py
├── test_users.py
```

---

Industry projects always have tests.

---

# .env File

Stores configuration.

Example:

```text
DATABASE_URL=postgresql://localhost
SECRET_KEY=abc123
DEBUG=True
```

---

# Why .env?

Never hardcode:

```python
password="admin123"
```

inside code.

---

Store secrets separately.

---

# requirements.txt

Contains project dependencies.

Generate:

```bash
pip freeze > requirements.txt
```

Example:

```text
fastapi==0.120.0
uvicorn==0.35.0
pydantic==2.x
```

---

Another developer installs:

```bash
pip install -r requirements.txt
```

Same environment.

# Interview Questions

### What is project initialization?

The process of setting up the project structure, dependencies, environment, and configuration before development.

---

### Why use virtual environments?

To isolate project dependencies and avoid version conflicts.

---

### What is the purpose of requirements.txt?

To store project dependencies and reproduce the environment.

---

### Why use .env files?

To store sensitive configuration separately from source code.

---

### Why separate routes, schemas, models, and services?

To improve maintainability, scalability, testing, and team collaboration.

# Golden Rule

For learning:

```text

```

is enough.

For industry:

```text
routes
schemas
models
services
database
core

```

must be organized from the beginning.

This separation is one of the biggest differences between a beginner FastAPI project and a production-ready FastAPI application.
