That format is:

# JSON

---

# What is JSON?

JSON stands for:

```text
JavaScript Object Notation
```

Despite its name:

```text
JSON ≠ JavaScript Only
```

It is used by:

* Python
* Java
* C#
* Node.js
* Go
* PHP
* FastAPI

almost every backend technology.

---

# Simple Definition

JSON is a lightweight text-based format used to exchange data between client and server.

Think of JSON as:

```text
English Language
        ↓
For Humans

JSON Language
        ↓
For Applications
```

---

# Real Life Example

Suppose a student submits a form.

Instead of:

```text
Name: Ravi
Age: 21
Course: CSE
```

Frontend converts it to:

```json
{
  "name": "Ravi",
  "age": 21,
  "course": "CSE"
}
```

This is JSON.

# JSON Syntax Rules

JSON consists of:

```text
Key : Value
```

Example:

```json
{
  "name":"Ravi"
}
```

---

# Keys Must Be Strings

Correct:

```json
{
  "name":"Ravi"
}
```

Wrong:

```json
{
  name:"Ravi"
}
```

---

# String Values

```json
{
  "name":"Ravi"
}
```

---

# Number Values

```json

  "age":21

```

---

# Boolean Values

```json

  "is_active":true
}
```

---

# Null Values

```json
{
  "middle_name":null
}
```

---

# Arrays

# Request Body

Now let's understand Request Body.

---

# What is Request Body?

Data sent from client to server.

Think:

```text
Client
   ↓
Sends Data
   ↓
Server
```

The data being sent is called:

```text
Request Body
```

---

# Example

Student Registration Form

Frontend sends:

```json
{
  "name":"Ravi",
  "age":21,
  "course":"CSE"
}
```

This JSON is Request Body.

---

# Request Flow

```text
Frontend
    |
    | Request Body
    |
    V
FastAPI
```

---

# What Happens Internally?

Suppose React sends:

```json
{
  "name":"Ravi"
}
```

Network can only transfer:

```text
Text
```

not Python objects.

So conversion happens.

This introduces:

```text
Serialization
Deserialization
```

---

# Serialization

Interview Favorite Question.

---

# Definition

Converting Python objects into JSON format.

---

Example

Python Dictionary:

```python
student = {
   "name":"Ravi",
   "age":21
}
```

Convert to JSON:

```json
{
  "name":"Ravi",
  "age":21
}
```

This conversion is:

```text
Serialization
```

---

# Easy Memory Trick

```text
Python Object
      ↓
JSON
```

Serialization

---

# Why Needed?

Because browser understands:

```text
JSON
```

not Python dictionaries.

---

# Real FastAPI Example

```python
@app.get("/student")
def get_student():
    return {
        "name":"Ravi",
        "age":21
    }
```

You returned:

```python
dict
```

But browser receives:

```json
{
  "name":"Ravi",
  "age":21
}
```

FastAPI automatically serialized it.

---

# Deserialization

Opposite process.

---

# Definition

Converting JSON into Python objects.

---

Example

Client sends:

```json
{
  "name":"Ravi",
  "age":21
}
```

FastAPI converts into:

```python
{
   "name":"Ravi",
   "age":21
}
```

This process is:

```text
Deserialization
```

---

# Easy Memory Trick

```text
JSON
   ↓
Python Object
```

Deserialization

---

# Complete Picture

Client sends:

```json
{
  "name":"Ravi"
}
```

↓

FastAPI converts to Python

↓

Business logic executes

↓

Python object generated

↓

FastAPI converts to JSON

↓

Client receives response

---

# Visual Lifecycle

```text
Client
   |
JSON
   |
   V
Deserialization
(JSON -> Python)
   |
   V
Business Logic
   |
   V
Serialization
(Python -> JSON)
   |
   V
Client
```

This happens for every API request.

# Golden Rule

Whenever an API works:

```text
Frontend
   |
JSON Request
   |
   V
Deserialization
(JSON → Python)
   |
Business Logic
   |
Serialization
(Python → JSON)
   |
   V
JSON Response
   |
Frontend
```

Memorize this flow. It is one of the most frequently asked concepts in backend interviews and the foundation for understanding FastAPI Request Bodies, Pydantic Models, Validation, and API Development.
