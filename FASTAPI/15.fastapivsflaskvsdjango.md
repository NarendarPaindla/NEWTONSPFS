# FastAPI vs Flask vs Django Performance Test

When students ask:

> "Is FastAPI really faster than Flask and Django?"

The correct answer is:

**It depends on the workload.**

Let's build the **same route** in all three frameworks and then load test them with:

```text
100 Concurrent Users
1000 Total Requests
```

---

# Test Scenario

We'll create a simple API:

```http
GET /hello
```

Response:

```json
{
  "message":"Hello World"
}
```

This is a CPU-light endpoint and useful for comparing framework overhead.

---

# FastAPI

Install:

```bash
pip install fastapi uvicorn
```

Code:

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")
def hello():
    return {"message": "Hello World"}
```

Run:

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

---

# Flask

Install:

```bash
pip install flask
```

Code:

```python
from flask import Flask, jsonify

app = Flask(__name__)

@app.route("/hello")
def hello():
    return jsonify({
        "message":"Hello World"
    })

if __name__ == "__main__":
    app.run(port=8001)
```

Run:

```bash
python app.py
```

---

# Django

Create project:

```bash
pip install django

django-admin startproject demo
```

views.py

```python
from django.http import JsonResponse

def hello(request):
    return JsonResponse({
        "message":"Hello World"
    })
```

urls.py

```python
from django.urls import path
from .views import hello

urlpatterns = [
    path("hello/", hello)
]
```

Run:

```bash
python manage.py runserver 8002
```



# Why FastAPI Wins Here

FastAPI uses:

```text
ASGI
+
Starlette
+
Uvicorn
+
Async Support
```

Architecture:

```text
Client
   ↓
Uvicorn
   ↓
Starlette
   ↓
FastAPI
```

Less overhead.

---

# Why Flask Is Slower

Flask uses:

```text
WSGI
```

Traditional synchronous request handling.

Architecture:

```text
Client
   ↓
Werkzeug
   ↓
Flask
```

Very simple but less efficient for high concurrency.

---

# Why Django Is Often Slower

Django brings many features:

```text
ORM
Authentication
Admin Panel
Middleware
Template Engine
Sessions
```

More functionality means more overhead.

Architecture:

```text
Client
   ↓
Django
   ↓
Middleware Stack
   ↓
View
```

---

# Real Industry Truth

Many students see benchmarks and conclude:

```text
FastAPI = Always Best
```

This is incorrect.

# Database Bottleneck Example

Suppose API does:

```python
students = db.query(...)
```

and database takes:

```text
200 ms
```

Then:

```text
Framework Time = 2 ms

Database Time = 200 ms
```

Changing Flask to FastAPI won't magically make it:

```text
202 ms → 2 ms
```

Database dominates.

---

# Async Example

FastAPI shines when waiting for:

```text
Database Calls
External APIs
Redis
File Uploads
Email Services
```

Example:

```python
@app.get("/data")
async def data():
    result = await fetch_data()
    return result
```

While waiting, FastAPI can process other requests.

# Interview Question

### Why is FastAPI generally faster?

Answer:

```text
FastAPI is built on ASGI using Starlette and Uvicorn,
supports asynchronous request handling,
and introduces less overhead for API workloads.
```

---

# Important Note for Students

Benchmark numbers vary significantly.

A benchmark showing:

```text
FastAPI = 6000 req/sec
Flask   = 2500 req/sec
Django  = 1800 req/sec
```

does **not** mean your application will automatically get those numbers.

Real-world performance depends on:

```text
Database
Network
Caching
Business Logic
Server Hardware
Deployment Configuration
```

The framework is only one piece of the performance puzzle.
