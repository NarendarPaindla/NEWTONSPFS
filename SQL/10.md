# Lesson 1: What is a View?

## Definition

A **View** is a **virtual table** created from one or more existing tables.

A View **does not store data itself** (except in some specialized databases with materialized views). It stores only the **SQL query**.

Whenever we access the View, MySQL executes the stored query and returns the latest data.

---

## Real-Life Example

Imagine a college.

The **Students** table contains:

| StudentID | Name  | Age | Salary | Password |
| --------- | ----- | --- | ------ | -------- |
| 101       | Rahul | 20  | 25000  | abc123   |
| 102       | Priya | 21  | 28000  | xyz789   |

Students should **not** see the Salary and Password columns.

Instead of creating another table, we create a **View**.

Student View

| StudentID | Name  | Age |
| --------- | ----- | --- |
| 101       | Rahul | 20  |
| 102       | Priya | 21  |

The original table remains unchanged.

# Lesson 2: Why Do We Need Views?

Views are used for:

* Security (hide sensitive columns)
* Simplicity (hide complex joins)
* Reusability (write a query once, use it many times)
* Data abstraction

---

# Lesson 3: Creating a View

## Syntax

```sql
CREATE VIEW view_name AS
SELECT column1, column2
FROM table_name;
```

---

## Example

Students Table

| StudentID | Name  | Age | Marks |
| --------- | ----- | --- | ----- |
| 101       | Rahul | 20  | 90    |
| 102       | Priya | 21  | 95    |
| 103       | Arjun | 19  | 82    |

Create View

```sql
CREATE VIEW StudentView AS
SELECT StudentID,
       Name,
       Marks
FROM Students;
```

---

# Lesson 4: View the Data

```sql
SELECT *
FROM StudentView;
```

Output

| StudentID | Name  | Marks |
| --------- | ----- | ----- |
| 101       | Rahul | 90    |
| 102       | Priya | 95    |
| 103       | Arjun | 82    |

Notice

We are querying the View instead of the original table.

# Lesson 5: Internal Execution Process

Suppose you execute

```sql
SELECT *
FROM StudentView;
```

### Internal Working

```text
Student Query

↓

StudentView

↓

Stored SQL Query

↓

Students Table

↓

Read Data

↓

Return Result
```

Important:

The View itself stores **only the query**, not the data.

# Lesson 6: Updating the Base Table

Suppose

```sql
UPDATE Students
```

Now run


Output

| StudentID | Name  | Marks |
| --------- | ----- | ----- |
| 101       | Rahul | 100   |
| 102       | Priya | 95    |
| 103       | Arjun | 82    |

The View automatically reflects the updated data.

# Lesson 7: Can We Insert Using a View?

Simple View

```sql
CREATE VIEW StudentNames AS
SELECT StudentID,
       Name
FROM Students;
```

Insert

```sql
INSERT INTO StudentNames
VALUES(104,'Sneha');
```

If the underlying table allows it and all required columns are satisfied, MySQL may allow this operation.

However, many complex Views are **not updatable**.

---

# Lesson 8: Updating Data Through a View

```sql
UPDATE StudentView
SET Marks = 96
WHERE StudentID = 102;
```

This updates the **Students** table because the View is based on it.

---

# Lesson 9: Replacing a View

Instead of dropping a View, use:

```sql
CREATE OR REPLACE VIEW StudentView AS
SELECT StudentID,
       Name,
       Age,
       Marks
FROM Students;
```

The View definition is replaced.

# Lesson 10: Dropping a View

```sql
DROP VIEW StudentView;
```

Result

The View is deleted.

The original `Students` table remains unchanged.

# Lesson 11: Views with JOIN

Departments

| DepartmentID | DepartmentName |
| ------------ | -------------- |
| 1            | CSE            |
| 2            | ECE            |

Students

| StudentID | Name  | DepartmentID |
| --------- | ----- | ------------ |
| 101       | Rahul | 1            |
| 102       | Priya | 2            |

Create View

```sql
CREATE VIEW StudentDepartmentView AS
SELECT
s.StudentID,
s.Name,
d.DepartmentName
FROM Students s
INNER JOIN Departments d
ON s.DepartmentID = d.DepartmentID;
```

---

Query

```sql
SELECT *
FROM StudentDepartmentView;
```

Output

| StudentID | Name  | DepartmentName |
| --------- | ----- | -------------- |
| 101       | Rahul | CSE            |
| 102       | Priya | ECE            |

# Lesson 12: Advantages of Views

| Advantage      | Explanation                  |
| -------------- | ---------------------------- |
| Security       | Hide sensitive columns       |
| Simplicity     | Hide complex SQL             |
| Reusability    | Write once, use many times   |
| Consistency    | Same logic for all users     |
| Easy Reporting | Create report-specific Views |

# Lesson 13: Limitations of Views

* A View does not store data separately.
* Complex Views are often not updatable.
* Performance depends on the underlying query.
* Dropping the base table makes the View unusable.

# Common Mistakes

## ❌ Assuming Views Store Data

Wrong Concept

```text
View stores another copy of data.
```

Correct

A View stores **only the SQL query**, not a separate copy of the data.

---

## ❌ Dropping the Base Table

```sql
DROP TABLE Students;
```

The View becomes invalid because its source table no longer exists.

---

## ❌ Updating Complex Views

Views created with joins, aggregate functions, or `GROUP BY` are often not updatable.
